# Repository instructions

- Implement one bounded vertical slice at a time: include the user experience, data, security, backend behavior, tests, and documentation needed by that slice.
- Do not add deferred features or broaden a slice beyond its agreed scope.
- Bias strongly toward the simplest, lowest-friction user experience. Prefer sensible defaults, optional guidance, and soft warnings over rigid workflows or hard constraints, except where security, data integrity, or an established need requires them.
- Treat active project membership as the data-security boundary. Do not expose project metadata or content to nonmembers.
- Run relevant formatting, linting, unit, integration, security-rule, end-to-end, and build checks after changes, and report their results.
- Explain and obtain approval for any proposed production dependency before adding it.
- Keep documentation consistent with implemented behavior, scope, decisions, and local development workflows.
